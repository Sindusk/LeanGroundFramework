# Why the steps say what they say

The incident behind each bracketed id in the stage files, under that file's name. Never loaded to follow a step; read the entry for one step only to challenge it. A retro that turns a lesson into a step adds its entry here and only a bracketed id to the step (`retro.md`).

The kit's first entries come from the projects it was extracted from: `AZ-` ids from Azothos (its lessons file and az-package skill), `PF-` ids from Polarity Fracture (its pf-package skill's why file). This project's own entries use its own prefix.

## SKILL.md

- **Recipes and needed seams [AZ-141]:** Azothos's package procedure ties both rules to AZ-141: use the recipe for a common addition rather than a past package's diff, and check each novel seam a block plans against what already holds the data. The incident is in Azothos's delivery record for AZ-141.
- **Falsifications per package [PF-541]:** the project asked for three to five falsifications per package, but each chunk was asked for three to five, so one package ran about a dozen, each a red run and a green run.

## cut.md

- **The rule attacked first [PF-537]:** three rule gaps each cost a mid-build correction, and a later review found three more where the rule met another system.

## handover.md

- **Unique markers [AZ-161]:** one round and a relaunch were lost to a fixture marker (a seal colour) that older fixtures also handed out, so a stale item in the tester's long-lived world gave a wrong read-out.
- **Sizes and values worked out [AZ-177]:** one round and a relaunch were lost to a screen sized 270 high when the real window gave 252; two steps besides expected results the rules did not give.
- **Reachable conditions [AZ-183]:** a planned check needed a state that never occurs in play, and a step was lost to a text width guessed rather than measured against the longest real name.

## dispatch.md

- **Produced as a list [PF-533]:** a chunk produced one value where the design allowed several, and was resumed to make it a list; names produced and consumed must match exactly.
- **Two site lists [PF-535]:** a chunk walking two site lists ran out of budget at 169k with no test written.
- **Exceptions name their effects; shared types [PF-536]:** "no zone effect lands on an ally" removed an ally's intended gain, found only at the manager's check; a chunk's added union member broke readers it did not list. Its "Read first" lacked the wiring points, so the chunk spent 30 calls before its first edit finding what the manager had found in two greps.
- **Named tests; DONE past budget [PF-537]:** "with witnesses" left tests unwritten across two chunks; a chunk returned DONE at 139 calls, and a budget nobody reads back is not one.
- **Under about 20 files is one chunk [PF-539]:** two mechanics split into separate chunks each spent 13 to 30 calls re-reading the same shared files before their first edit; packages of 15 to 20 files cost less as one session.
- **The harness's count; declarations by name [PF-541]:** a chunk reported about 113 calls and the harness 134; each cold start spent 13 to 30 calls reading files where a by-name lookup prints only the body needed.
- **Fresh over resumed [PF-534, PF-553]:** chunks resumed at 106k to 300k of context re-read the whole context on every call; a fresh chunk briefed on the remainder cost less.
