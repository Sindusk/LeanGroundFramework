# package: retro

Run only when the owner asks, in a session of its own, about every five closed packages or once a week. A session changes no skill, note or tool for a lesson but queues it in `docs/agent-notes/lessons.md`: a package at most three (`close.md`), other work at most two [MM retro 2026-11-14].

1. **Measure.** With the owner's cost script, if any, since the last retro: cost per package and per thousand non-document lines changed, the phase shares (opening, build, manual check, after the close), cost per check round, the share of first chunks over budget, peak context, tool-result volume and calls by command; compare with "Last retro" in `lessons.md` [AZ retro 2026-11-02, PF retro 2026-11-15]. Without one, use the lessons and say so.
2. **Choose.** Act on a lesson that recurs or that the measures show costing turns or context; drop one seen once that cost little. Each change's commit body names the cost it targets and the figure to move. What the figures cannot yet answer is queued as a measurement, its decision rule fixed before the data.
3. **Change** a stage file, `where-things-live.md`, `tools/project_docs.py` or a hook: name the failure class and rewrite the rule that covers it, never a second beside it; enforce only where it would hold [PF retro 2026-11-15]. The step gets a bracketed id, `why.md` the story. Prefer a mechanical check to prose; trim before raising a budget.
4. **Verify:** `python -m unittest discover -s tools` if a tool changed, then `python tools/docs.py check`. **Audit the pathways:** each next step a skill or agent names resolves (the command exists, a quoted heading is real, no "(planned)" outlives its build) [MM pathway audit 2026-11-14].
5. **Record:** remove the lessons acted on or dropped; rewrite "Last retro" with today's date, the step 1 figures and the exact command that measured them. Commit `Retro: <what changed>`, push if CLAUDE.md says so.
6. **Back to the kit:** a core-file change (`tools/leanground.json` lists them) serving every project is offered to the owner for the kit: file and change, one line. Take a newer kit with `python tools/upgrade.py <kit>`, dry run first.
