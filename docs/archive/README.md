# Documentation archive

Delivery records, concluded working documents and executed plans, kept so a past decision can be reconstructed. **Nothing here is authoritative or startup reading.** Current rules live in `DESIGN.md`, reasons in `design-history.md`, process rules in `CLAUDE.md` and `docs/agent-notes/`; where an archived file disagrees with them, they win.

Archived text is never rewritten, so archived files cite each other and the design by the names and section numbers they had when written.

## Layout

- `initiatives/`: one delivery record per Initiative (a standalone package gets its own), and its working document when it had one.
- `programmes/`: executed plans and one-off programmes that were not Initiatives.

## Naming

`YYYY-MM-DD-<subject>-<kind>.md`, lowercase and hyphenated. The date is when the Initiative's record opened (its working document takes the same date, so the pair sorts together), or when the work concluded for anything else. The kind is `-record`, `-working-document` or `-plan`.
