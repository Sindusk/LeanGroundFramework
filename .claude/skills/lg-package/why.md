# Why the steps say what they say

The incident behind each bracketed id in the stage files, under that file's name. Never loaded to follow a step; read the entry for one step only to challenge it. A retro that turns a lesson into a step adds its entry here and only a bracketed id to the step (`retro.md`).

The kit's first entries come from the projects it was extracted from: `AZ-` ids from Azothos (its lessons file and az-package skill), `PF-` ids from Polarity Fracture (its pf-package skill's why file), `MM-` ids from Metallic Meridian (its working agreements and lessons). This project's own entries use its own prefix.

## SKILL.md

- **Recipes and needed seams [AZ-141]:** Azothos's package procedure ties both rules to AZ-141: use the recipe for a common addition rather than a past package's diff, and check each novel seam a block plans against what already holds the data. The incident is in Azothos's delivery record for AZ-141.
- **Sized from the block, seams written once [PF-539]:** packages of 15 to 20 files cost $7 to $15 as one session, and the smallest dispatched chunk cost $3.64. Azothos's earlier trigger, dispatching past 200k of context after reading, fired once and its build cost more than an inline one. An audit of ten manager sessions found 16k to 25k of each opening was code bodies the chunks then read again.
- **Inline under about twelve files [PF-523, PF-540]:** PF-523's seams were 10 files, and three auditors' 211k tokens bought what one search and a few excerpts did. PF-540's audit beside its predecessor's build commit missed two of seven targets and found nothing the commit's file list did not. Azothos's one-Grep threshold for a Haiku seam map had not run for nine days of packages when its retro retired it.
- **The hard stop [PF-533]:** "about 25" calls was not one: an audit took 40 calls and 76k tokens, and still missed two seams its chunk found.
- **Sonnet for a row-to-field audit [PF-633]:** a Haiku audit answered "none found" for 10 of 18 rows whose fields existed; the manager re-read about 15 files.
- **Checking reports [PF-520]:** a check of the audit searched two of the three source trees, and a helper reading the old list reached review.
- **Windows over 40 lines [PF-542]:** an opening printed a 90-line window and parts of three more files, though the rule was already written; the plan cited a few names from each.
- **Word boundaries [PF-531]:** a bare seam name matched every longer word containing it and returned 33KB.
- **A tool's verdict before the rules [AZ-145]:** Azothos's retro of AZ-145's lessons let a tool whose verdict shapes the rules (curated data that must pass a new check) run before the rules commit; its commit gives no figure.
- **The exact text attacked [PF-537, PF-614, PF-622]:** Polarity Fracture's owner added the build-time attack after PF-537's rule gaps (under cut.md). Later attacks checked kinds of action but not other writers of the state the rule writes (three interactions found in review), its arithmetic (PF-621) or the acting entity's own case (PF-628); PF-622's review found three exclusions the rule stated and no test covered.
- **Baseline before the first edit [PF-519, PF-576, PF-528]:** PF-519 found its predecessor's suite red only at its own verification; PF-576's baseline stopped at its first failure, so an inherited failure cost a second whole run; PF-528's baseline died on a dropped connection caused by its own first edits. A failure's start is proven by a red run at the parent commit; one green run here proves nothing.

## build.md

- **Needed seams [AZ-141]:** as under SKILL.md.
- **Falsifications per package [PF-541]:** the project asked for three to five falsifications per package, but each chunk was asked for three to five, so one package ran about a dozen, each a red run and a green run.
- **Anchors by `git grep` [AZ-145]:** added by the same retro as the tool's verdict (under SKILL.md), with no figure recorded.
- **A second run for varying tests [AZ-198]:** five new tests moved an existing placement-dependent test to the edge of the test grid, where it failed 4 of 5 runs, costing three extra runs and a stash run.
- **Fixtures from a real output [MM-139]:** a log parser's fixture was written from memory with the wrong cause string, and its pre-launch check never ran in the target's folder layout, so the probe took three launches and lost the live state it was meant to read.
- **Long runs on final code [MM-101]:** the first real runs used code a mid-run fix then changed, so their numbers had to be re-derived to show the fix left them unchanged.
- **A wait on the answer line [MM-110]:** a wait on a loose pattern matched a startup line, so the run went on before the command it waited for had answered.
- **The owner's machine [MM-144]:** load readings started unannounced while the owner used the machine; they were stopped and run again.

## cut.md

- **The rule attacked first [PF-537]:** three rule gaps each cost a mid-build correction, and a later review found three more where the rule met another system.
- **Read, never inferred [PF-599, PF-673]:** plans named a status kind the code did not have (a chunk blocked after about 100 calls), a helper that could not work where it was named, a line no reader printed, and a test board that could not cross the rule's threshold, so its falsification stayed green.
- **Never "the owner runs" [MM-102]:** the handover asked the owner to run a command and read a template; the owner does neither, and a round was lost.
- **Inputs exist; stand-ins are the owner's [AZ-191]:** a block with no item to show chose a stand-in itself, and the owner rejected it in two rounds.
- **Check before naming [MM-110, MM-121, MM-142, MM-144, MM-106]:** a third-party command named from memory was incomplete in the version used, so two of four runs exported nothing; a config was assumed to land per-environment and lived elsewhere, costing a rules rewrite; a planned extension point could not register what the feature needed; "copied with its MIT notice" covered files whose own headers said GPL; a saved format taken from the repository was rewritten whole by the editor's first save.

## handover.md

- **Unique markers [AZ-161]:** one round and a relaunch were lost to a fixture marker (a seal colour) that older fixtures also handed out, so a stale item in the tester's long-lived world gave a wrong read-out.
- **Sizes and values worked out [AZ-177]:** one round and a relaunch were lost to a screen sized 270 high when the real window gave 252; two steps besides expected results the rules did not give.
- **Reachable conditions [AZ-183]:** a planned check needed a state that never occurs in play, and a step was lost to a text width guessed rather than measured against the longest real name.
- **No live log watch [AZ-191, MM-145]:** the manual check was 29% of a package session's cost, and AZ-191's alone $4.68 over four relaunches, while a watched log made each of its events a whole turn. MM-145's watch woke the agent for a turn per command the owner typed. Both projects reversed the watch: launch, end the turn, read the log on the report.
- **No reply to an exit notice [AZ-209]:** the owner wanted no reply at all to a launched app's completion notice, where the rule had allowed one line.
- **Consumed items in the always-run part; values by name [AZ-173]:** the checklist's supplies sat in the run-once setup, which a tester with the setup already built skips, so 8 steps were never reached; an earlier fixture passed one argument in another's position, so a world setting never applied and saved state was polluted.
- **Objects by exact kind [AZ-160]:** a step placed a variant the fixture never gave, worked round by hand.
- **Objects made mid-checklist [AZ-196]:** a step read details of an object the tester had made during the run, which lacked the state the fixture gives its own objects, so nothing showed.
- **Fixed points [AZ-167]:** placement steps were read as chained from the last part placed rather than from the fixed point the author meant.
- **The dry run [AZ-198]:** two of 20 steps were wrong, a debug command's argument form and an object already locked to one value expected to take another, each caught only in the round.
- **The agent runs the commands [MM-102]:** as under cut.md.
- **Render before the owner [PF-529]:** two layout defects passed every unit test and the browser case, and showed in the first still.
- **A mock-up in chat first [MM-127]:** both sample rounds went before the owner before the agent had seen them drawn, and three rounds of visual work were rejected.

## dispatch.md

- **Produced as a list [PF-533]:** a chunk produced one value where the design allowed several, and was resumed to make it a list; names produced and consumed must match exactly.
- **Two site lists [PF-535]:** a chunk walking two site lists ran out of budget at 169k with no test written.
- **Exceptions name their effects; shared types [PF-536]:** "no zone effect lands on an ally" removed an ally's intended gain, found only at the manager's check; a chunk's added union member broke readers it did not list. Its "Read first" lacked the wiring points, so the chunk spent 30 calls before its first edit finding what the manager had found in two greps.
- **Named tests; DONE past budget [PF-537]:** "with witnesses" left tests unwritten across two chunks; a chunk returned DONE at 139 calls, and a budget nobody reads back is not one.
- **No cap, no shared-shape exception [PF-627]:** across 181 first chunks, 34 ran past 120 calls at $3.90 each against $1.51 for one under 90, 27% of chunk spend, and 26 finishers followed. Three chunks accepted at S 2 to 3 because they shared a shape ran 134, 168 and 153 calls; one left unsplit to stay at four chunks ran 130. A K 0 chunk under the exception ran 108 calls and 152k.
- **What counts as a site list [PF-632]:** a ward read by three families was tallied S 1 and ran 180 calls; chunks adding four and five production fields ran 155 and 135.
- **About four tests with K ≥ 1 [PF-541]:** three chunks at or under six tests each ran past 120 calls (134, 145, 139); the largest files' cold-start reading alone was near 60k.
- **Fast and slow tiers apart [PF-543]:** seven tests plus two browser cases in one chunk ran past 150k.
- **One check, one chunk [PF-599]:** a row planned a chunk after its partner broke the consistency check joining them, so neither chunk could go green alone.
- **The harness's count; declarations by name [PF-541]:** a chunk reported about 113 calls and the harness 134; each cold start spent 13 to 30 calls reading files where a by-name lookup prints only the body needed.
- **Fresh over resumed [PF-534, PF-553]:** chunks resumed at 106k to 300k of context re-read the whole context on every call; a fresh chunk briefed on the remainder cost less.
- **Every reader by name [PF-632]:** three of six reports left a source unwired under "every source"; a review found the three readers a plan had named only as a group.
- **Act on arrival [PF-540]:** after a report arrived, the manager ended its turn to wait for the notice's context size and sat idle 18 minutes until the owner asked; nothing depended on that figure.
- **Open only the doubtful renders [PF-542]:** every image a manager opens stays in its context for the rest of the package.
- **Refresh shared state [PF-558, PF-675]:** a chunk that raised the content version left the next browser chunk refused on the seed check in six packages; in PF-675 no browser chunk followed, so the gate's database step went red, costing a gate resume.

## close.md

- **Lessons appended by command [MM-101]:** MM-101's close rewrote the lessons file instead of appending to it and lost its header and the previous package's lines.
- **Stop what the session started [PF retro 2026-11-15]:** over three weeks agents started the gate, the readiness check or a restart 234 times and the stop command 30, so dev servers and watchers outlived almost every package; Azothos added a leftover-process check at its close for the same reason.

## retro.md

- **Routine sessions queue two; weekly [MM retro 2026-11-14]:** Metallic Meridian's trial batches, outside any package, queued at most two lines each from 2026-11-10 beside a package's three, and its retros ran every five packages or once a week.
- **Measures [AZ retro 2026-11-02, PF retro 2026-11-15]:** Azothos measured $5.31 a package and $7.06 per thousand lines, and one package's extra check rounds at $4.68, about $0.8 to $1.0 a round; Polarity Fracture found 34 of 181 first chunks past their budget, 27% of chunk spend, and counted 234 starts against 30 stops by command. Metallic Meridian's "Last retro" names the exact commands it measured with.
- **The class, not a second rule [PF retro 2026-11-15]:** a lesson appended beside the rule it sharpens leaves two rules of unequal strength, and the next change is measured against whichever the agent read first. Its retro queued a measurement with the decision already fixed (mostly cheaper-model defects means dropping cheaper-model chunks).
- **Audit the pathways [MM pathway audit 2026-11-14]:** an audit of every skill's named next steps found a tool name only one agent had, a quoted heading that was not a heading, a command the skill never mentioned, and "(planned)" marks on things already built.
